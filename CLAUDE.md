# FleetTrack — context for Claude

Real-time delivery tracking platform (portfolio project). When changing code, explain *why*
(problem → decision → trade-off), not just *what*.

## Stack (versions matter — don't "upgrade" or downgrade)
- Java 21 (Temurin), Spring Boot **4.1.0** (Spring Framework 7, Hibernate 7.4, **Jackson 3** = `tools.jackson.*`, Flyway 12)
- PostgreSQL 16 + PostGIS 3.4, Kafka (KRaft), Redis 7, STOMP WebSockets
- Micrometer + Prometheus + Grafana, Testcontainers, Docker, Kubernetes, GitHub Actions
- Maven, base package `com.fleettrack`. Windows 11 dev machine, IntelliJ IDEA, Docker Desktop (WSL2).

## Commands
- Infra: `docker compose up -d` (PostGIS :5432, Kafka :9092, Redis :6379, Prometheus :9090, Grafana :3000)
- Run app: `mvn spring-boot:run` or run `FleettrackApplication` in IntelliJ → http://localhost:8080
- Unit + web-slice tests (no Docker): `mvn test`
- Everything incl. Testcontainers ITs (`*IT`, needs Docker): `mvn verify`
- Demo data: `python scripts/simulate.py`
- Reset dev DB (e.g. Flyway checksum mismatch): `docker compose down -v && docker compose up -d`

## Conventions — follow these
- Layering: controller → service → repository. Controllers stay thin; business rules live in entities/services.
- Constructor injection only. No Lombok (plain Java keeps entity behaviour explicit).
- DTOs are Java records with Bean Validation; entities never leave the service layer.
- Errors: throw `ResourceNotFoundException` (404), `ConflictException` / `InvalidStateTransitionException` (409),
  `BadRequestException` (400). `GlobalExceptionHandler` maps them to RFC 9457 ProblemDetail. Never build error
  responses in controllers.
- Delivery status changes ONLY via `Delivery#transitionTo` / `#assignTo` (rules in `DeliveryStatus`). No setters.
- Schema changes ONLY via a new Flyway file `src/main/resources/db/migration/V{n}__description.sql`.
  Never edit an applied migration. `ddl-auto` stays `validate`.
- Geography columns are GENERATED by Postgres from lat/lng and are NOT mapped in entities; spatial queries
  are native SQL in repositories (no hibernate-spatial).
- Do not use the KNN operator `<->` together with `FOR UPDATE` (PostgreSQL error "attempted to lock invisible
  tuple"); order by `ST_Distance` in locking queries.
- Kafka payloads are JSON strings (`EventJson`), keyed by courierId / deliveryId. Domain code publishes Spring
  events; `KafkaEventPublisher` forwards them AFTER_COMMIT. Each consumer concern has its own consumer group.
- Metrics tags must be low-cardinality (never courierId / deliveryId).
- Every new behaviour gets a test: unit test for domain logic, `@WebMvcTest` for HTTP mapping,
  `*IT extends AbstractIntegrationTest` when it touches PostGIS/Kafka/Redis.

## Layout
- `courier/`, `location/`, `delivery/` — feature packages (entity, repository, service, controller, dto/)
- `events/` — event records; `messaging/` — Kafka topics, publisher, error handling (retry → `.DLT`)
- `tracking/{eta,notification,metrics,live}` — Kafka consumers
- `realtime/` — WebSocket config + Redis pub/sub fan-out; `static/index.html` — live map
- `k8s/`, `monitoring/`, `.github/workflows/ci.yml`, `Dockerfile`, `docker-compose.yml`
